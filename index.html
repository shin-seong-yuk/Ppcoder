PROJECT 01

UNITY · C# · URP · WEBGL

MeFense↗

수학(Math)과 디펜스(Defense)를 결합한 3D FPS 타워 디펜스 게임입니다. 플레이어가 직접 전투와 건설에 참여하며, 포탑마다 부여된 수학적 항을 연결해 시간에 따라 변화하는 포탑의 성능을 설계합니다.

기간 3개월형태 개인 프로젝트역할 기획·개발 전담
사용 기술Unity 6C#URPInput SystemAI NavigationWebGL

제작 계기

단순한 수치 업그레이드를 넘어 수학 자체가 전략이 되는 게임을 만들고 싶었습니다. 같은 포탑과 카드를 얻더라도 수식 구성, 배치 위치, 전력망 설계에 따라 다른 전략이 만들어지도록 했습니다.

구현한 시스템

게임 규칙부터 수식 계산, 포탑 AI, 전력망, 절차적 맵 생성, 전투·웨이브와 UI까지 직접 구현했습니다. 지형·사거리·전력 연결·포탑 배치를 함께 고려하는 전투 구조를 구성했습니다.

설계하며 고민한 부분

  • 수학을 쉽게 이해하면서도 전략적으로 활용할 수 있는 구조
  • 특정 연산·함수 하나에 치우치지 않는 밸런스
  • 직접 전투와 포탑 방어가 서로를 대체하지 않는 역할 분배
  • 무작위 맵과 웨이브에서도 판단과 실력이 반영되는 플레이

배포 환경에서의 완성도

WebGL의 한글·수학 기호·셰이더 표시 문제를 로그로 분석하고, UI와 화면 비율을 조정했습니다. 실제 웹에 10회 이상 재배포해 확인하고 전용 빌드 메뉴로 반복 설정을 자동화했습니다.

PROJECT 02

UNITY · C# · 3D PUZZLE ACTION

EXIT_FROM↗

자신의 행동을 기록하고 재현하는 ‘고스트’를 이용해 실험실을 탈출하는 3D 탑뷰 퍼즐 액션 게임입니다. 퍼즐을 풀어가는 과정에서 타인을 도구로 바라보는 시선에 질문을 던집니다.

기간 6개월형태 개인 프로젝트역할 기획·개발 전담
사용 기술UnityC#행동 기록·재생3D Top-View레벨 디자인UI 시스템

고스트와 퍼즐

기록된 행동을 재생하는 고스트로 압력판과 장치를 작동하고, 플레이어와 다른 경로를 이동합니다. 레이저·움직이는 발판·고스트 전용 문·색 변환 발판을 조합해 난이도를 높였습니다.

시스템이 이야기가 되도록

친근하던 고스트가 점차 플레이어를 의심하고 비난하며, 익숙했던 퍼즐 풀이를 불편한 선택으로 바꿉니다. 단순한 캡슐 캐릭터와 마지막 시점 전환을 ‘타인을 도구로 보는 시선’이라는 주제에 연결했습니다.

개발 방식의 변화

모든 기믹을 미리 완성하려 했지만, 구현과 테스트에 따라 재미도 달라졌습니다. 이후 수정·확장이 쉬운 구조와 기존 장치의 재조합을 중심으로 개발 방식을 바꿨습니다.

회고

기획·구현·레벨 디자인·UI·연출을 혼자 맡으며, 디자인의 제약을 작품의 개성으로 바꿨습니다. 장애물의 수보다 공간의 흐름이 중요하며, 기획은 제작 중 발견한 문제를 해결하며 다듬어진다는 것을 배웠습니다.

PROJECT 03

UNITY · C# · TEAM PROJECT · SOCIAL DEDUCTION

Not A Cat↗

고양이 마피아 조직에 숨어든 첩자 ‘삵’을 찾아내는 직업 기반 심리 게임입니다. 각 고양이와 삵은 고유한 직업과 능력을 사용하며, 미션과 대화 속에서 서로의 정체를 추리합니다.

기간 2026.07 ~ 진행 중형태 6인 팀 프로젝트역할 기획·개발
사용 기술UnityC#게임 규칙 시스템미션 시스템텍스트 채팅보이스 채팅

게임 콘셉트

고양이들 사이에 숨은 삵을 찾아내는 마피아형 심리 게임입니다. 직업별 특성과 능력, 미션 수행과 대화를 통해 정보를 모으고 상대의 정체를 추리합니다.

기획

맵 구성과 직업 구성, 게임 규칙과 전체 흐름을 설계했습니다. 플레이어가 이동·미션·토론을 거치며 자연스럽게 의심과 판단의 근거를 만들도록 구성했습니다.

개발

맵 구현, 게임 로직 설정, 미션 구성과 구현을 담당했습니다. 기획 단계의 규칙이 실제 플레이 흐름으로 이어지도록 시스템을 연결했습니다.

멀티플레이 소통

플레이어가 상황과 정보를 교환할 수 있도록 텍스트 채팅과 보이스 채팅을 구현했습니다. 심리전의 핵심인 대화가 게임 안에서 이어지도록 했습니다.

PROJECT 04

UNITY · C# · STEAM MULTIPLAYER · PHYSICS PARTY

Elevator↗

엘리베이터라는 제한된 공간에서 최후의 1인이 남을 때까지 무기로 싸우는 멀티플레이 물리 파티 게임입니다. 층이 바뀔 때마다 등장하는 방해 요소를 버티며 전투를 이어갑니다.

형태 개인 프로젝트역할 기획·개발 전담플레이 싱글 AI · Steam 멀티플레이
사용 기술Unity 6C#Netcode for GameObjectsSteamworks.NETInput SystemURPAI Navigation

핵심 전투

좁은 엘리베이터 안에서 무기를 획득하고 상대와 싸워 최후의 1인이 되는 전투를 구성했습니다. 제한된 공간 자체가 전투의 긴장감을 만드는 구조입니다.

층별 방해 요소

엘리베이터가 층에 도착할 때마다 새로운 방해가 등장합니다. 플레이어는 상대뿐 아니라 매 층의 환경 변화에도 대응해야 합니다.

Steam 멀티플레이

Steam 로그인 후 방을 생성하거나 참가하고, 엘리베이터 대기실에서 준비 상태를 맞춘 뒤 방장이 게임을 시작하는 흐름을 구현했습니다.

싱글과 멀티

싱글에서는 AI 3·5·7명과 전투할 수 있고, 멀티에서는 Steam을 통해 다른 플레이어와 한 판을 구성합니다. 전체 기획과 개발을 혼자 담당했습니다.

ABOUT ME

GAME DEVELOPMENT PROGRAMMER

문제를 끝까지 파고들고,
직접 구현해 답을 찾습니다.

궁금한 것은 직접 만들어보며 배웁니다. 게임을 기획하고 구현해 실제 사용자에게 내놓은 뒤, 예상과 다른 반응을 다음 개선의 출발점으로 삼습니다.

첫 게임을 배포했을 때 튜토리얼이 없어 플레이어가 시작부터 헤매는 모습을 보았습니다. 그때 제가 아는 것을 사용자도 당연히 알 것이라 생각했다는 점을 깨달았습니다. 이후에는 기능이 에디터에서 동작하는 것만으로 완성이라 여기지 않습니다. MeFense의 WebGL 문제를 끝까지 추적하고 실제 배포 화면을 반복 확인한 것도 같은 이유입니다.

원인을 좁혀 해결합니다

문제가 생기면 막연히 더 노력하기보다 로그와 실행 환경을 확인해 원인을 나눕니다. 수정 후에는 실제 사용자 환경에서 다시 검증합니다.

상대가 이해할 수 있게 전달합니다

수학 강사로 일하며 학생마다 막히는 지점을 찾아 수식·그림·예시로 설명했습니다. 개발 협업에서도 추상적인 말을 프로토타입과 화면으로 바꿔 공통 이해를 만듭니다.

직접 만들며 배웁니다

개인 게임의 기획·개발·배포를 경험했고, 팀 프로젝트에서는 서로 다른 관점을 구현 가능한 규칙과 흐름으로 연결해 왔습니다.

AI를 작업에 맞게 활용합니다

게임의 코드 작성과 구조 설계 과정에서 AI를 보조 도구로 사용합니다. Elevator의 모델 제작에도 활용했고, MeFense에서는 AI로 만든 텍스처 아이콘을 적용해 웹 환경의 UI 표현을 통일했습니다.
